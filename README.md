## 这是什么

8 个 [Claude Code Skill](https://docs.claude.com/en/docs/claude-code/skills)，组成一个完整的雅思备考闭环：**练习 → 诊断 → 归档 → 聚合 → 计划 → 再练习**。

| Skill | 一句话 | 典型触发 |
|-------|--------|---------|
| `/ielts` | 总入口：摸底建档、状态汇报、路由、备份迁移 | 「我要备考雅思」「今天练什么」 |
| `/ielts-writing` | 写作四维批改 + 句子级标注 + 改写对比，自动归档 | 「批改作文」+ 粘贴题目和作文 |
| `/ielts-reading` | T/F/NG 逻辑拆解 + 错题诊断，同义替换跨篇入库 | 「这道为什么错」+ 粘贴文章和答案 |
| `/ielts-listening` | 听力题型追踪 + 错因诊断 + 精听任务生成 | 「剑 19 T1 错了 10 个」+ 错题清单 |
| `/ielts-speaking` | 万能故事库（跨会话复用）+ Part 3 预测 + 表达升级 | 「Part 2 描述一次旅行怎么准备」 |
| `/ielts-vocab` | 生词本 Leitner 间隔重复 + 同义替换专项测验 | 「今天复习单词」「考考我」 |
| `/ielts-plan` | 聚合全部数据做诊断，生成落实到天的训练计划 | 「我现在什么水平」「帮我做计划」 |
| `/ielts-dashboard` | 本地 React 可视化 + 数据体检 + 状态栏安装 | 「看看我的进度」「打开 dashboard」 |

**核心理念**（继承自 v1.0）：不教英语，帮你在雅思这套规则里拿最高分。总分 = 四科平均且 .25/.75 向上取整，所以听力阅读（技巧分，提得快）拿 80% 的时间，写作口语（能力分，提得慢）守住底线配置即可。

**v3.0 的增量**：教练有了记忆。每次批改、每套错题、每个故事、每组替换词都会归档成本地 Markdown 文件——练得越多，诊断越准，计划越个性化。

### 方式一：一键脚本

```powershell
# Windows：在仓库目录双击运行，或在终端执行
install.cmd
```

```bash
# macOS / Linux / Git Bash
./install.sh
```

### 方式二：手动复制

```bash
git clone <本仓库地址>

cp -r ielts ielts-writing ielts-reading ielts-listening ielts-speaking ielts-vocab ielts-plan ielts-dashboard ~/.claude/skills/
```

### 验证安装

重启 Claude Code，输入 `/ielts`。看到教练开始问「目标分数是多少」就装好了。

**第 1 分钟 —— 建档**：

```
你：/ielts
AI：你的目标分数是多少？考试时间定了吗？考 Academic 还是 General？
你：目标 7，9 月 20 号，A 类
AI：你现在大概什么水平？做过模考吗？
你：上次考了 6.0，听力 6 阅读 6.5 写作 5.5 口语 5.5
AI：每天能拿出多少时间备考？
你：2 小时
AI：→ 创建 ~/.ielts/profile.md
   → 差距分析：目标 7.0 = 听力 7.5 + 阅读 7.5 + 写作 6 + 口语 6（27/4=6.75→7.0）
   → 今天建议：写作（差距最大且 AI 批改价值最高）
```

**接下来的每一天** —— 做完练习直接把材料丢给对应 skill：

```

你：今天复习单词                        → 到期队列测试 + 盒子更新
```

**每周日 —— 复盘**：

```
你：/ielts-plan
AI：读全部归档 → 差距表 + 练习结构 + 高频错误 Top 5 + 下周逐日计划 → 写入 plan.md
```

**随时 —— 看图**：

```

AI：启动本地网页 http://localhost:5173
```

## 八个 Skill 详解

### `/ielts` — 总入口

- **新用户**：3 个问题摸底 → 创建档案 → 差距分析 → 路由
- **老用户**：开场输出状态卡（倒计时 / 最近成绩 / 最近 7 天练习分布 / 今日建议）→ 路由
- **今日建议算法**：优先「差距最大且最近 3 天没练」的科目，并列时选写作；考前 7 天切换为保手感模式
- **管理功能**：备份 / 恢复 / 修改档案（改目标分、改考期）
- 内置四科算分公式和听力阅读换算表（所有子 skill 共享引用）

### `/ielts-writing` — 写作批改

三种模式：**审题**（只给题目）、**批改**（题目 + 作文）、**练习**（让它出题）。

批改输出：四维评分（TR/CC/LR/GRA，按官方 band descriptor）→ 逐段逐句标注（引用原句 + 归维度 + 给改法）→ **改写对比**（升级到目标分版本，每处修改标注原因，改写后重新评分）→ 提分优先级 → 与上一篇的对比（分数变化 + 旧错因是否复发）。

批改后自动做三件事：归档全文到 `writing/`（带评分和标准错误标签）、把改写中最有复用价值的词汇升级对沉淀进同义替换库、汇报归档位置。

> 校准提醒：AI 评分普遍偏高约 0.5 分，看趋势别看绝对值；模板文会被锁死在 6 分以下。

### `/ielts-reading` — 阅读精读

三种模式：**错题分析**（文章 + 题目 + 你的答案）、**精读训练**（引导做题，不直接给答案）、**专项训练**（点名练某题型）。

核心是逐题推导链：定位原文句 → 提取同义替换对 → 错因归类 → 完整推导过程。T/F/NG 有专门的三步判定逻辑（原文提没提 → 一致/矛盾/信息不足），并覆盖五大陷阱（部分匹配、程度偏移、错误归因、过度概括、缺失修饰）。

每次分析后：归档（含题型级 对/总 统计）+ 同义替换词表**追加**进 `vocab/synonyms.md`（查重、只追加不重写、历史积累永不丢失）。

### `/ielts-listening` — 听力错题教练

不陪你听音频——音频自己放，它负责把错题变成两样东西：**准确的错因诊断**和**能执行的精听任务**。

报分时给出错题三元组（题号 + 你写的 + 正确答案）效果最好。输出：题型统计 → 逐题错因（10 个标准标签：拼写 / 单复数 / 数字 / 干扰项 / 替换没反应 / 跟丢 / 地图方位 / 没来得及审题 / 口音 / 粗心）→ 丢分模式识别（重复出现的错因才是信号）→ 四步精听法周任务（盲听 → 逐句听写 → 对照标红 → 影子跟读，具体到分钟）。

内置各题型方法论：选择题等转折词再落笔、地图题手指跟随法、S4 信号词跟踪等。

### `/ielts-speaking` — 口语素材工厂

**故事库是长期资产**：5 个万能故事（旅行 / 人物 / 物品技能 / 事件 / 媒体）覆盖 80%+ 的 Part 2 话题。遇到新话题的第一反应永远是「已有的哪个故事能盖住它」，映射不上才生成新故事。

四种模式：话题映射（默认入口）、话题分组（题库聚类 + 覆盖率计算）、故事生成（真实经历优先 + Part 3 预测 + 入库）、表达升级（保持口语自然感 + 记录练习次数）。

**故事维护**随时响应：改写、合并、删除、自建组别（题库换季时）、换题季体检。你手改过的故事以你的版本为准。

### `/ielts-vocab` — 词汇教练

**Leitner 间隔重复**：box1=1 天 → box2=2 天 → box3=4 天 → box4=7 天 → box5=15 天。答对升箱，答错回炉，box5 连续通过两轮毕业进「已掌握」。

四种模式：
- **今日复习**（默认）：自动算出到期队列（一次最多 15 词），测试形式按 box 递进——低箱认知（见词说义）、中箱语境（例句填空）、高箱产出（造句判搭配）
- **添加生词**：丢词进来，自动补全释义 / 搭配 / 雅思例句入库
- **同义替换专项**：从累计库抽测（阅读听力的解题命脉），库存不足时用内置高频包起步
- **主题词汇包**：按话题给产出级词汇（雅思 7 分作文用得上的，不给 GRE 冷词）

词库完全尊重你的习惯：可加自定义列（记法 / 音标），手改的释义不会被「纠正」，说「这词我熟了」就直接升箱。

### `/ielts-plan` — 诊断与计划

全量聚合消费者（只读各文件 frontmatter，不撑爆上下文）。铁律：**每个结论都有数据出处，数据不够就直说**（记录 < 3 条时给摸底周计划，不硬编诊断）。

诊断：四科现状测量（含 raw 分换算）→ 差距表（用总分公式反推四科配置）→ 练习结构（14 天频次 + 断练警告）→ 高频错误 Top 5（按「技术性速效 / 方法性 / 积累性」分类）→ 趋势。

计划：按剩余天数分四阶段（基础 / 提升 / 冲刺 / 考前），落实到每天做什么 + 用哪个 skill + 量化验收目标，按 80% 执行率设计（留弹性补欠账），写入 `plan.md`。

### `/ielts-dashboard` — 可视化与运维

四个功能：**启动 Dashboard**（见下节）、**文本概览**（无 Node 时的降级模式，终端输出统计卡）、**数据体检**（zod 校验全部数据文件，坏了帮你定位修复）、**状态栏安装**（见下下节）。

## 数据目录：你的备考资产

所有数据在 `~/.ielts/`（可用环境变量 `IELTS_HOME` 重定向到任意位置），**纯 Markdown + YAML frontmatter**——用任何编辑器都能打开、手改、搜索，永远不会被格式绑架。

```
~/.ielts/
├── profile.md        # 档案：目标分、考期、现状、每日时间
├── plan.md           # 当前训练计划（/ielts-plan 生成，覆盖式更新）
├── writing/          # 每篇批改归档：2026-07-26-task2-technology.md
├── reading/          # 每次阅读分析归档
├── listening/        # 每次听力诊断归档
├── speaking/
│   ├── stories/      # 万能故事库（长期资产，文件名不带日期）
│   └── *.md          # 练习记录
└── vocab/
    ├── synonyms.md   # 同义替换累计库（单文件表格）
    └── words.md      # 生词本（单文件表格 + Leitner 字段）
```

frontmatter 是各 skill 之间的数据接口。一个归档示例：

```yaml
---
schema: writing.v3
date: 2026-07-26
task: 2
type: discussion
topic: "儿童学外语的起始年龄"
words: 268
band: {tr: 5.5, cc: 6.0, lr: 5.5, gra: 5.0, overall: 5.5}
target: 6.5
error_tags: [gra-tense, lr-collocation, tr-underdeveloped]
---
（正文：题目 / 原文 / 完整批改报告，留给人看）
```

**错误标签体系**是错题本和热力图的数据源：写作 17 个、阅读 10 个、听力 10 个、口语 9 个标准标签（完整表见 [`docs/DATA-SCHEMA.md`](./docs/DATA-SCHEMA.md)）。标签统一，跨会话聚合才有意义。

**可修改、可扩展**（重要设计承诺）：

- 标准集（故事组别、错误标签、词表列）只是**推荐起点**——题库换季、生活变化时，可以自建组别（kebab-case）、给词表加自定义列（记法 / 音标），聚合端宽容处理
- 「只追加不重写」的保护规则防的是 AI 意外覆盖，**不是限制你**：你明确要求的修改、删除、合并、批量导入，skill 都会照做（先复述改动再执行）
- 你手工编辑过的内容（故事细节、词条释义）以你的版本为准，AI 不会「改回去」

机器校验的权威 schema 在 `ielts-dashboard/assets/app/server/schema.mjs`（zod），人读规范在 `docs/DATA-SCHEMA.md`。

## Dashboard 可视化

```
你：/ielts-dashboard
```

首次启动会 `npm install`（国内网络慢会自动换 npmmirror 镜像），之后启动 dev server 并打开 `http://localhost:5173`。**纯本地：数据不出你的电脑。**

页面内容（浅色 / 深色自动跟随系统）：

| 区块 | 内容 |
|------|------|
| 状态卡 | 考试倒计时 · 目标分 · **今日建议**（带理由）· 今日到期词汇 · 累计资产 |
| 写作走势 | overall 加粗 + TR/CC/LR/GRA 细线，看趋势不看绝对值 |
| 四科雷达 | 现状 vs 目标虚线框，raw 分自动换算 band，无数据科目有警示 |
| 高频错误 Top 10 | 按科目着色的条形图——你的错题本聚合视图 |
| 错题热力图 | 错误标签 × 最近 8 周，越深越频繁，一眼看出哪个毛病在收敛 |
| 14 天练习频次 | 断练的科目就是下一个丢分的科目 |
| 同义替换库 | 全库可搜索表格 |

**数据体检**：对 `/ielts-dashboard` 说「检查数据」，它会跑 `npm run validate` 用 zod 校验所有文件的 frontmatter，输出每个文件的 PASS/FAIL 和具体字段错误，并帮你修复。

刷新页面即重新读取数据。没有 Node？照样能用——skill 会直接在终端里输出文本版概览。

## 状态栏集成

让 Claude Code 底部常驻一行备考状态：

```
🎯IELTS 7.0 | 剩55天 | 今日:写作·听力 ✓
```

对 `/ielts-dashboard` 说「装状态栏」，它会先试跑脚本确认输出，再经你确认后把下面的配置合并进 `~/.claude/settings.json`（脚本零依赖，直接 node 运行）：

```json
{
  "statusLine": {
    "type": "command",
    "command": "node <skills目录>/ielts-dashboard/assets/app/scripts/statusline.mjs"
  }
}
```

重启 Claude Code 生效。说「卸载状态栏」即移除。

## 备份与迁移

对 `/ielts` 说「备份数据」即可，或手动执行（Git Bash / macOS / Linux 通用）：

```bash
# 本机快照
cp -r ~/.ielts ~/ielts-backup-$(date +%Y%m%d-%H%M%S)

# 打包成单文件（换电脑）
tar -czf ~/ielts-backup.tgz -C ~ .ielts

# 新电脑还原
tar -xzf ielts-backup.tgz -C ~
```

数据是纯文本 Markdown——网盘同步、git 仓库、U 盘拷贝都天然兼容。

## 常见问题与排查

**Q：`npm install` 很慢或失败？**
国内网络用镜像：`npm install --registry=https://registry.npmmirror.com`（skill 失败时会自动尝试）。

**Q：Dashboard 页面空白或报错？**
多半是某个数据文件的 frontmatter 被手改坏了。对 `/ielts-dashboard` 说「检查数据」定位到具体文件和字段，按提示修复。

**Q：5173 端口被占用？**
Vite 会自动换端口，以启动输出里的实际 URL 为准。

**Q：AI 打的分和真实考试差多少？**
普遍偏高约 0.5。把 AI 评分当趋势仪表，不当预测器；重要节点建议用 2-3 个工具交叉验证。

**Q：换了目标分 / 考试改期了？**
直接对 `/ielts` 说「目标改成 7.5」「考试改到 11 月」，它会更新档案并复述改动。

**Q：数据能给多个人用吗？**
每个系统用户一份 `~/.ielts/`。同一账号想隔离多套数据，用 `IELTS_HOME` 环境变量指向不同目录。

**Q：Windows 下手动编辑数据文件要注意什么？**
保存为 UTF-8 编码（VS Code 默认即可）；不要用 `echo >>` 往数据文件追加内容——Windows 命令行的编码会把中文写坏。

**Q：卸载？**
删除 `~/.claude/skills/` 下的 8 个 `ielts*` 目录即可。学习数据在 `~/.ielts/`，想留就留。

## 设计原则

1. **教学优先，数据其次** —— 归档失败不阻塞批改：skill 永远先把教练该做的事做完，最后才提持久化问题。
2. **frontmatter 是接口，正文留给人** —— 聚合分析只读文件头部 30 行，上下文不爆炸；完整报告留在正文里随时翻看。
3. **只追加，不重写** —— 累计型文件（词库）只允许追加行和单行编辑，几个月的积累不会毁于一次 AI 手滑；但你本人的显式维护请求永远优先。
4. **统一标签，宽容扩展** —— 错误标签是推荐的封闭集（聚合的前提），同时允许 kebab-case 自建扩展（与时俱进的前提）。
5. **数据必须有出处** —— 诊断和计划里的每个数字都能追溯到具体归档文件；数据不够就直说，不编。
6. **纯本地** —— 没有云端、没有账号、没有遥测。数据格式是开放的 Markdown，随时可以带走。

## 评测数据

v3.0 发布前跑过一轮对照评测（5 个核心场景 × 新版 / 基线各一次，36 条客观断言，基线为 v1.0 旧版或无 skill，详见 `ielts-v3-workspace/iteration-1/benchmark.md`）：

| | 断言通过率 | 平均耗时 | 平均 tokens |
|--|-----------|---------|------------|
| v3.0 | **97.2%**（35/36） | 574 s | 67.5k |
| 基线 | 75.0%（27/36） | 507 s | 62.0k |

关键结论：基线模型的**教学内容**并不弱，v3 的差距集中在**数据契约**上——标准错误标签（基线自造标签导致聚合失效）、标准归档位置（基线写进自创目录）、词汇沉淀（基线为零）、工具闭环。这正是「跨会话记忆能积累起来」的前提。

已知限制：AI 评分偏高约 0.5 分（业界通病，已内置校准提醒）；单次评测样本量小，欢迎实际使用反馈。
